## Two Phase Commit 이란? 

분산 트랜잭션에서 일관성을 보장하기 위한 프로토콜이다.
MSA 환경이라고 한다면, 도메인별로 서버가 분리되어있는 상태에서 A 서버에서 관련 책임에 맞게 처리하고, B 서버에서 B 도메인에 대한 책임에 맞게 처리를 하여 총 2번 이상으로 처리를 하는 것이다. 
예를 들어, 상품에 대한 결제를 한다고 했을 때 처리프로세스는 다음과 같다. 
1. 상품에 대한 재고를 확인하고, 차감
2. 결제 진행, 완료

결제서비스와 상품서비스가 분리되어있고, 재고관리는 상품서비스에서 한다고 가정하자. 
그러면 다음과 같다. 
1. 결제 서비스에서 API 요청을 받음
2. 상품서비스에 재고 차감을 요청
3. 상품서비스에서 재고가 있는지 확인하고, 차감하고, 응답한다. 
4. 완료가 되면 결제서비스에서 결제를 한다. 

서버간의 네트워크 통신을 하는동안 사용자는 기다려야하는데 하나의 서버에서 하는 것보다 복잡도가 올라갔기 때문에 만약 상품서비스에서 응답속도가 느리거나 네트워크 통신오류로 인해 하나의 서버에서 하는 것보다 오류가 생길 가능성이 더 커진다.

만약 상품에 재고 차감한다음에 결제단계에서 실패를 했다면 상품 재고를 원래의 상태로 돌려놓아야하는데 그건 어떻게 진행할 수 있을까? 

내가 해결할 궁금증은 다음과 같다. 
1. 일관성 유지 방법
2. 트랜잭션 도중에 실패할 경우 장애를 어떻게 전파할지
3. 분산 환경에서 희생해야할 부분이 뭔지
