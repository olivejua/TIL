
Spring Boot 내 스케줄러는 싱글스레드 환경이라 별도의 설정이 없다면 싱글스레드 환경에서 실행을 하게 된다. 
여러개의 작업을 등록해놓았다면 동일시간에 여러개의 작업이 실행을 해야하는 환경이라면 1개의 작업이 먼저 실행되고 나머지 작업이 대기하게 된다.

```java
@Slf4j  
@Component  
public class CustomScheduler {  
  
    // 매 1초마다 실행  
    @Scheduled(fixedRate = 1000)  
    public void runTask1() throws InterruptedException {  
        log.info("[task1] Start: {}", LocalTime.now());  
        Thread.sleep(5_000);  
        log.info("[task1] End: {}", LocalTime.now());  
    }  
  
    @Scheduled(fixedRate = 1000)  
    public void runTask2() throws InterruptedException {  
        log.info("[task2] Start: {}", LocalTime.now());  
        log.info("[task2] End: {}", LocalTime.now());  
    }  
}
```

1. Thread명이 동일하여 1개의 스레드가 두개의 작업을 번갈아 실행하고 있는 것이 보인다.
2. 또한가지는 task1은 5초가 걸리면 그시간안에 실행해야하는 작업들이 대기열에 계속해서 쌓일 것 같다. 예시를 보면 task1실행하는 사이에 task2는 5번을 실행했어야하니 대기열에 task2가 5개가 쌓였을것 같은데 결과를 보면 번갈아서 1번씩 실행되는것을 볼 수 있다. 
   이유는 먼저 예정되어있는 작업이 실행 완료되어야 다음 작업을 예약하기 때문이다.

### 실행 흐름 설명
- **0초:** `runTask1` 실행 시작 → 5초 동안 블로킹
- **1초:** `runTask2`는 대기 상태로 들어감 (스레드가 바쁘기 때문에 즉시 실행 불가)
- **5초:** `runTask1` 실행 완료
- **5초:** 바로 `runTask2` 실행 시작
- **6초:** `runTask1` 실행 (예약 시간이 도래) → 대기열에 추가됨
- **6초:** `runTask2` 완료 후, 즉시 `runTask1` 실행


작업들이 대기열에서 밀리지 않고, 병렬처리를 하려면 스레드 설정이 필수적이라고 봐야한다. 
그럼 스레드풀을 10개로 설정해놓으면 모두 밀리지 않고 실행할 수 있겠다.

```java
@Configuration  
public class SchedulerConfig {  
  
    @Bean  
    public ThreadPoolTaskScheduler taskScheduler() {  
        ThreadPoolTaskScheduler scheduler = new ThreadPoolTaskScheduler();  
        scheduler.setPoolSize(10);  
        scheduler.initialize();  
  
        return scheduler;  
    }  
}
```

2. Task1은 5초마다 대기하고 있지만 여유스레드가 있기 때문에 다른 스레드로 실행할 것 같은데 여전히 1개의 스레드가 종료되고 나서 다음 작업이 실행된다. 이건 이전처럼 실행중인 Task가 종료되어야 다음차례를 예약할 수 있기 때문이다.

그렇다면 같은 Task의 완료여부를 떠나 주기가 되었을 때 실행하거나 병렬로 같은 Task를 실행하려면 어떻게 해야할까? 

1. Async로 비동기 실행을 하여 Task를 전달하고, 스케줄러 Task는 종료하여 다음 차례를 이어서 예약할 수 있도록 한다.
2. Spring Batch 처리


하지만 실행중인 작업이 끝나지도 않았는데 다음 작업을 실행하면 여러스레드를 병렬로 장시간 잡아놓는다는 뜻이니 에러처리나 실행제한시간을 두는 것이 좋다.
